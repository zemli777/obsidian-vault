## Зачем нужна база знаний

База знаний не просто хранит файлы, а показывает связи между информацией. Она помогает быстро находить ранее изученное, документировать решения, восстанавливать контекст проектов, повторно использовать инструкции и видеть пробелы в знаниях.

Граф — визуальное представление этих связей. Заметка становится узлом, а конструкция `[[Другая заметка]]` создаёт связь между узлами.

```text
[[Linux]]
   ├── [[Docker]]
   │      ├── [[Docker Compose]]
   │      └── [[Контейнеризация]]
   ├── [[systemd]]
   └── [[Сетевые настройки]]
```

Цель графа — не красивая картинка, а обнаружение изолированных заметок, крупных тематических областей и неожиданных связей.

## Рекомендуемая структура vault

```text
Vault/
├── 00 Inbox/
├── 10 Projects/
├── 20 Areas/
├── 30 Knowledge/
├── 40 Resources/
├── 50 Archive/
├── Journal/Daily/
├── Templates/
├── Attachments/
└── Dashboards/
```

- `00 Inbox` — необработанные идеи и быстрые записи.
- `10 Projects` — работы с конкретным результатом или сроком.
- `20 Areas` — постоянные сферы ответственности.
- `30 Knowledge` — основные знания и технические заметки.
- `40 Resources` — книги, статьи и внешние материалы.
- `50 Archive` — завершённые проекты и устаревшие материалы.
- `Dashboards` — обзорные страницы Dataview.

Для старта достаточно четырёх папок: `Inbox`, `Projects`, `Knowledge`, `Templates`.

## Первая связанная заметка

Создайте `30 Knowledge/Docker.md`:

```markdown
---
type: knowledge
status: active
created: 2026-08-20
tags: [linux, containers]
---

# Docker

Docker — платформа для запуска приложений в изолированных контейнерах.

## Основные понятия

- [[Docker image]]
- [[Docker container]]
- [[Docker volume]]
- [[Docker network]]
- [[Docker Compose]]

## Связанные темы

- [[Linux]]
- [[Контейнеризация]]
- [[Kubernetes]]

## Источники

- https://docs.docker.com/
```

Ссылки могут указывать на ещё не созданные заметки. Щёлкните по такой ссылке, когда будете готовы заполнить материал.

## Внутренние и обратные ссылки

Основные варианты:

```markdown
[[Название заметки]]
[[Docker network|сети Docker]]
[[Docker#Основные понятия]]
![[Docker]]
![[Docker#Где применяется]]
```

Если `Kubernetes.md` ссылается на `[[Docker container]]`, в заметке Docker появится обратная ссылка на Kubernetes. Панель **Backlinks / Обратные ссылки** отвечает на вопрос: где ещё используется эта информация?

Полезная ссылка объясняет отношение:

```markdown
[[Docker]] использует namespaces и cgroups ядра [[Linux]] для изоляции процессов.
```

Фраза `См. [[Docker]]` создаёт связь, но почти не объясняет её смысл.

## Папки, теги и ссылки

- Папка показывает, где хранится заметка: `30 Knowledge/Linux`.
- Тег показывает тип или состояние: `#project`, `#draft`, `#meeting`.
- Ссылка показывает смысловое отношение между понятиями.

Не создавайте сотни тегов заранее. Именно внутренние ссылки формируют полезный граф.

## Свойства заметки

Минимальный набор:

```yaml
---
type: knowledge
status: active
created: 2026-08-20
updated: 2026-08-20
tags: [linux]
aliases: [GNU/Linux]
---
```

Добавляйте только те свойства, которые действительно используются для поиска, сортировки или Dataview-запросов.

## Карты содержания MOC

MOC — обзорная заметка-навигатор по теме:

```markdown
---
type: moc
tags: [moc, linux]
---

# Linux

## Основы

- [[Файловая система Linux]]
- [[Права доступа Linux]]
- [[Процессы Linux]]

## Администрирование

- [[systemd]]
- [[Журналирование Linux]]
- [[Настройка сети Linux]]

## Контейнеризация

- [[Docker]]
- [[Podman]]
- [[Контейнеризация]]
```

MOC создаёт понятную навигацию и центральный узел тематического графа.

## Автоматический обзор через Dataview

Создайте `Dashboards/База знаний.md`:

````markdown
# База знаний

## Недавно изменённые заметки

```dataview
TABLE file.mtime AS "Изменена", type AS "Тип", status AS "Статус"
FROM "30 Knowledge"
SORT file.mtime DESC
LIMIT 20
```

## Необработанные материалы

```dataview
LIST
FROM "00 Inbox"
SORT file.ctime DESC
```

## Изолированные заметки

```dataview
LIST
FROM "30 Knowledge"
WHERE length(file.inlinks) = 0 AND length(file.outlinks) = 0
SORT file.name ASC
```
````

Последний запрос находит заметки, которые ещё не связаны с базой.

## Настройка графа

Откройте `Ctrl+P → Graph view: Open graph view`.

Полезный фильтр:

```text
-path:"Templates" -path:"Attachments"
```

Создайте цветовые группы:

```text
path:"10 Projects"
path:"30 Knowledge"
tag:#moc
tag:#daily
```

Например, проекты сделайте оранжевыми, знания — синими, MOC — фиолетовыми, ежедневные заметки — серыми.

Глобальный граф со временем перегружается. Для повседневной работы полезнее локальный граф: `Ctrl+P → Graph view: Open local graph`. Установите глубину `2`, чтобы видеть прямые и соседние связи текущей заметки.

## Ежедневный процесс

1. Быстро сохраните новую информацию в `00 Inbox`.
2. При обработке дайте заметке понятное название.
3. Добавьте краткое содержание и источник.
4. Поставьте один-два тега.
5. Добавьте минимум одну смысловую ссылку.
6. Переместите заметку в `Projects`, `Areas` или `Knowledge`.
7. Добавьте её в тематическую MOC, если это важный материал.

## Еженедельное обслуживание

```markdown
# Еженедельный обзор

- [ ] Разобрать Inbox
- [ ] Проверить активные проекты
- [ ] Обновить ближайшие задачи
- [ ] Связать изолированные заметки
- [ ] Перенести завершённое в Archive
- [ ] Проверить Git backup
```

Не пытайтесь построить идеальную структуру заранее. Она должна развиваться вместе с реальными материалами.

## Как понять, что система работает

База знаний приносит пользу, если вы можете быстро найти нужную информацию, восстановить причину технического решения, увидеть связанные проекты, повторно использовать инструкции и вернуться в контекст после долгого перерыва.

Главный критерий — не количество заметок и не красота графа, а скорость, с которой база помогает принять решение или выполнить работу.
